# FFmpegを使った音声デコード・MP4統合

aural Studio のタイムライン音声ミックスは、通常のPCM WAVならFFmpegなしでも書き出せます。MP3・FLAC・AAC/M4A・OGG・圧縮WAVなどのデコード、および既存映像へのMP4統合には、FFmpegのコマンドライン実行ファイルが必要です。

## FFmpegの設定

アプリは次の順でFFmpegを探します。

1. 環境変数 `FFMPEG_BINARY` に指定された実行ファイル
2. PATH上の `ffmpeg` / `ffmpeg.exe`
3. アプリ・リポジトリ内の一般的な同梱場所

見つからない場合は、OSに応じてFFmpegをインストールするか、実行ファイルの絶対パスを `FFMPEG_BINARY` に設定してください。

### Windows

FFmpegのWindowsビルドを用意し、例えば次のように設定します。

```powershell
$env:FFMPEG_BINARY = "C:\tools\ffmpeg\bin\ffmpeg.exe"
ffmpeg -version
```

FFmpegをアプリに同梱する場合は、`ffmpeg.exe` だけでなく、そのビルドが必要とするDLLも一緒に配置してください。

### macOS

Homebrewを利用する場合:

```bash
brew install ffmpeg
ffmpeg -version
```

### Ubuntu / Debian

```bash
sudo apt update
sudo apt install ffmpeg
ffmpeg -version
```

## タイムライン音声の書き出し

「タイムライン → 音声ミックスをWAVに書き出す...」を選ぶと、有効でミュートされていないAudio/Voiceクリップをタイムライン位置に配置し、重なりを加算したステレオ48kHz/16bit PCM WAVを出力します。クリップの音量、フェードイン、フェードアウト、素材内の開始位置が反映されます。

PCM WAV以外の素材は、FFmpegでクリップ区間だけをステレオfloat PCMへデコードしてから同じミキサーで処理します。元の素材ファイルは変更しません。

## 完成映像への音声統合

「タイムライン → 完成映像にタイムライン音声を統合してMP4に書き出す...」を選び、先に合成しておいた映像ファイルと出力先を指定します。

- 映像ストリーム: 再エンコードせずコピー
- 音声ストリーム: AAC、標準192kbps
- 出力: MP4
- 映像・音声の短い方に合わせて終了

映像を再エンコードしないため、入力映像はMP4コンテナへストリームコピー可能なコーデックである必要があります。H.264映像を推奨します。未対応コーデックの場合は、H.264などの互換性がある形式で合成済み映像を作ってから再実行してください。

出力は一時ファイルに作成し、FFmpegが成功した場合だけ指定先へ置き換えます。選択した入力映像・タイムライン音声素材を出力先に指定して上書きすることはできません。


## タイムライン全体をMP4に書き出す

「タイムライン → タイムライン全体をMP4に書き出す...」では、プロジェクト内の有効な動画クリップと静止画クリップを、トラック順に合成してMP4へ出力できます。音声/Voiceトラックに有効なクリップがある場合は、同じタイムライン位置・音量・フェードを反映したミックスを作り、AAC音声として映像へ統合します。音声クリップがない場合は無音のMP4を出力します。

- 動画クリップ: 素材内の開始位置、長さ、タイムライン上の配置を反映
- 静止画クリップ: 表示時間とタイムライン上の配置を反映し、アルファ付き画像は透過を維持
- 字幕クリップ: 台本の最新テキストを半透明背景付きでタイムライン位置へ焼き込み
- レイヤー順: トラック一覧の上から順に合成し、後のトラックを前面へ配置
- 出力解像度: 最初の動画クリップの解像度。静止画だけの場合は1920×1080
- 出力フレームレート: タイムラインのフレームレート
- 映像: H.264 (libx264)、CRF 20

字幕テキストは台本の行IDと対応付け、タイムライン上の開始時刻・長さで白文字＋半透明黒背景として焼き込みます。台本テキストを編集してから書き出すと、最新の台本内容が反映されます。日本語字幕には日本語対応フォントが必要です。WindowsはYu Gothic/Meiryo、macOSはヒラギノ、Ubuntu/Debianは `fonts-noto-cjk` を利用できます。別フォントを使う場合は `VOSE_SUBTITLE_FONT` にフォントファイルのパスを指定してください。

組み込み2Dプレースホルダーキャラクターと、対応する保存モーションJSONは動画へ焼き込めます。VRM/FBX/GLB等の外部3DモデルとVMDファイルのオフライン描画は未対応です。未対応の3D素材をキャラクタークリップに指定した場合は、書き出しを中止して理由を表示します。

動画素材がある場合はFFmpegに加えてFFprobeが必要です。通常のFFmpeg配布物には両方が含まれます。FFmpeg/FFprobeの実行ファイルは PATH、アプリ内の同梱場所、または `FFMPEG_BINARY` / `FFPROBE_BINARY` で指定できます。出力中もGUIは応答し、入力素材は上書きしません。



## 2Dキャラクターと保存モーションの書き出し

タイムラインメニューの「2Dキャラクタークリップを追加...」から、組み込みの2Dプレースホルダーを配置できます。キャラクターは左下へ透過合成されます。VoiceトラックのPCM16 WAVが重なる区間では、既存の音量・母音解析を使って口パクを生成します。Voiceクリップのsource-in、音量、フェードも口の動きに反映します。

保存モーションは `.motion.json` 形式です。素材追加時に「motion」として認識され、Motionトラックへ配置できます。対応するキーフレーム項目は次のとおりです。

- 頭部: x / y (メートル)、tilt_deg (度)
- 表情: blend_shapes の任意の0〜1値
- 母音: A / I / U / E / O の0〜1値
- 腕: LeftUpperArm / LeftLowerArm / RightUpperArm / RightLowerArm のクォータニオン
- mouth_openness: 0〜1

最小サンプル:

```json
{
  "format": "aural-motion",
  "version": 1,
  "keyframes": [
    {
      "time": 0.0,
      "mouth_openness": 0.0,
      "head": {"x": 0.0, "y": 0.0, "tilt_deg": 0.0},
      "blend_shapes": {"Joy": 0.0},
      "bones": {"LeftUpperArm": [0.0, 0.0, 0.0, 1.0]}
    },
    {
      "time": 1.0,
      "mouth_openness": 0.8,
      "head": {"x": 0.05, "y": 0.0, "tilt_deg": 12.0},
      "blend_shapes": {"Joy": 1.0},
      "bones": {"LeftUpperArm": [0.0, 0.0, 0.5, 0.8660254]}
    }
  ]
}
```

キーフレームの値は線形補間され、ボーン回転はクォータニオン補間されます。Motionクリップのsource-inも反映します。v1では同じ時間帯に重ねられるMotionクリップは1つです。


ライブモーションキャプチャを録画する場合は、先にプロジェクトを保存し、「モーションキャプチャ → 録画開始／録画停止・タイムラインに保存」を使用します。録画したVMC/WebSocketデータはプロジェクト管理下の `.motion.json` 素材として保存され、Motionトラックへ配置されます。手動作成した `.motion.json` も同じ形式で読み込めます。
